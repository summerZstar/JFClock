# {{项目名}} 前端通用规范

## 一、复用优先（硬约束）

新增任何 hook / 组件 / 工具函数 / API 封装前，**必须先查下表**；表里已有就复用，没有才允许自建。
自建完成后**必须补进本表**。

### 1.1 可复用能力索引（按项目实际填写）

> 填写要点：写清「入参 / 返回值 / 典型用法」，AI 靠这个判断能不能直接套。

| 类别 | 能力 | 路径 | 何时用 |
|------|------|------|--------|
| 脚手架 | CRUD API 工厂（如 `createCrud`） | | 标准增删改查接口，默认已含 page/detail/create/update/delete/batchDelete |
| 脚手架 | 表格逻辑 hook（如 `useTable`） | | **所有列表页表格逻辑统一用它，禁止重写** |
| 脚手架 | 表单逻辑 hook（如 `useForm`） | | **所有新增/编辑弹窗用它，禁止重写** |
| 脚手架 | 字典 hook | | 下拉选项取字典 |
| 请求 | HTTP 封装 | | 统一拦截器、token、错误处理；禁止直接裸用 axios/fetch |
| 组件 | 通用表格 / 表单 / 弹窗 / 上传 | | 优先用公共组件，不要各页面各写一套 |
| 状态 | 全局 store 模块 | | 跨页面共享状态 |
| 工具 | 日期 / 金额 / 加解密 / 权限判断 | | 不要自己写 |
| 约定 | 路径别名 | | 见构建配置，禁止深相对路径 |
| 约定 | 路由注册方式 | | 见权威规范 |

### 1.2 复用纪律

- 表格逻辑统一走表格 hook，表单逻辑统一走表单 hook，**禁止在页面里重写**
- 接口统一走 HTTP 封装，禁止绕过拦截器
- 新增页面前先看已有同类页面，照最接近的那个改

## 二、页面标准结构

```
src/pages/{模块}/{页面名}/
├── index.vue     列表页（搜索 + 表格 + 操作列）
└── save.vue      新增/编辑弹窗（表单）
```

- 搜索条件、表格列、操作按钮的写法参照权威规范中的模板
- 页面内不写请求细节，请求走 API 层
- 路径别名统一，禁止 `../../..` 深层相对路径

## 三、浏览器测试规范（硬性）

**前端页面功能必须通过浏览器自动化在真实浏览器中验证**，肉眼观察页面效果；
**不得仅通过接口调用断言前端功能** —— 接口通不代表页面能用。

### 3.1 基本要求

1. **工具**：Playwright（Python 或 Node 版本按项目既有约定，不要混用）
2. **脚本位置**：统一放约定目录（如 `{{测试脚本目录}}`）
3. **截图管理**：测试过程中生成的截图**用完立即删除**，不得留在仓库
4. **命名**：`test_{模块}_{场景}.py`，如 `test_login_success.py`、`test_user_crud.py`
5. **不要新增两套并行的写法**：新脚本统一用推荐框架（如 pytest + 公共 fixture）

### 3.2 测试前准备

- 确认后端已启动，并记录版本与端口
- 确认前端 dev server 就绪
- 优先用项目已有的登录脚本 / 公共 fixture 完成登录，不要每个脚本重复实现登录

### 3.3 定位元素原则

| 场景 | 推荐方式 |
|------|----------|
| 按钮 | `button:has-text("按钮文字")` |
| 输入框 | `input[placeholder*="提示文字"]` |
| 表格操作 | 用更具体的选择器，避免匹配多个 |
| 多个同文字按钮 | 加 CSS 类限定，或用 `.first` / `.nth()` |

### 3.4 等待策略

- 页面加载：`wait_until='networkidle'`
- 元素出现：`locator.wait_for(timeout=...)`
- 固定等待 `wait_for_timeout` **仅用于等待结果可观察**，不要滥用

### 3.5 验证到什么程度

- 至少验证：页面能打开、关键元素可见、核心操作能完成、结果与预期一致
- 涉及弹窗、批量操作、权限差异的，要分别覆盖
