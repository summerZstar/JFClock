# agents-rule —— AI 协作规范模板包

> 给任意新项目搭 `AGENTS.md` 的通用模板，**独立于任何具体工程**，可直接复制给其他项目使用。
> 本包位置：`_infra/docs/agents-rule/`（工作区内 master 源，多仓共享时**不删**）。
> 最后更新：2026-09-24

## 这套模板解决什么问题

AI 编码助手的行为主要靠两个文件约束：

- **入口文件 `AGENTS.md`**：定「规矩」——该怎么做、有什么红线
- **权威规范**（如 `docs/开发规范.md`）：定「写法」——具体编码约定

实践中常年缺第三层：**「项目已经有哪些可复用的能力」**。缺了这一层，AI 会把框架里已有的基类、工具类、hook、组件重写一遍，你只能事后返工。

本模板包把约束拆成三层，并强制每层都显式列出「可复用能力索引」。

## 文件清单

| 文件 | 性质 | 适用 |
|------|------|------|
| `common.md` | 协作规范：开发原则 / 文档同步 / 提交 / 红线 | 任何项目必备 |
| `backend.md` | 后端技术栈规范：复用索引 + 测试形态 | 后端项目选它 |
| `frontend.md` | 前端技术栈规范：复用索引 + 浏览器测试 | 前端项目选它 |
| `project-skeleton.md` | 项目专属章节骨架（概览/架构/环境/速查/常见坑） | 任何项目必备 |

全栈项目：`common.md` + `backend.md` + `frontend.md` + `project-skeleton.md` 全用；
单栈项目：`common.md` + 对应技术栈一份 + `project-skeleton.md`。

## 一、给新项目起手（五步）

1. **复制**：把本目录三个 / 四个文件复制到项目根目录（或直接在本目录下操作，生成后清理）
2. **合并**：写入项目根目录 `AGENTS.md`，**保留各自的标记块**不要拆散（见第三节）
3. **填占位符**：替换 `{{占位符}}`。**能填则填，暂时没有对应内容的原样留着**，并登记进文末台账（见第二节）
4. **建 `LOCAL.md`**：本机绝对路径、私有端口、本地账号等敏感值写这里，并加进 `.gitignore`
5. **收尾**：新项目里默认**删掉复制进来的 `agents-rule/`**（见第四节）；**本工作区 master 包 `_infra/docs/agents-rule/` 永不删**

## 二、占位符：不必一次填完

新项目常有「还没文档站」「还没部署文档」这类情况，占位符填不上是正常的，**不要为了填而硬编或直接删掉**——删了就没人记得还欠这一项。

做法：把填不了的占位符**原样留在正文里**（保持可见），同时在 `AGENTS.md` 末尾维护一张台账（模板已含，见 `project-skeleton.md` 末节）：

```markdown
## 待填占位符

| 占位符 | 出现位置 | 缺什么 | 什么条件下能补 |
|--------|----------|--------|----------------|
| `{{文档站路径}}` | 协作规范 §2.1 | 还没有文档站 | 文档站建好后 |
```

以后条件具备时，搜 `{{` 就能一次找全，照台账逐条替换并划掉。

## 三、标记：保留，且长期保留

每个文件的最外层由成对标记包裹：

```
<!-- BEGIN: 协作规范 -->   ...   <!-- END: 协作规范 -->
<!-- BEGIN: 后端规范 -->   ...   <!-- END: 后端规范 -->
<!-- BEGIN: 前端规范 -->   ...   <!-- END: 前端规范 -->
<!-- BEGIN: 项目信息 -->   ...   <!-- END: 项目信息 -->
```

**生成 `AGENTS.md` 后不要删标记**，它有两个长期用途：

| 用途 | 说明 |
|------|------|
| 可同步 | 将来可用脚本从外部源（本模板包）刷新整个块，一次更新所有项目 |
| 可手动改 | 标记块外是项目自有内容，随意手改；标记本身也给了"这一段的边界在哪"的锚点 |

**一条必须遵守的纪律**：标记块内的内容以**外部源**为准。如果你直接手改了块**内**的内容，下次从外部源同步时会**被覆盖**。想让手改长期生效，两个办法：

- 改到标记块**外**去（推荐，块外永远是项目自有地盘）
- 同时把改动回写到外部源（适用于这条规范对所有项目都该生效的情况）

改标记文字前，先确认没有脚本依赖它。

## 四、生成后收尾：新项目里的 `agents-rule/` 用完即删

默认做法（**针对被初始化的新项目**）：**复制 → 生成 `AGENTS.md` → 删除该项目内的 `agents-rule/`**。
本工作区的 master 源固定在 `_infra/docs/agents-rule/`，**不随新项目走、也不在本工作区删除**。

删除前自检三项：

- [ ] `AGENTS.md` 里没有**该填却没填**的占位符（填不了的已在台账登记，这是允许的）
- [ ] `LOCAL.md` 已建好并已进 `.gitignore`
- [ ] 没有把本 README 一并并进 `AGENTS.md`（README 讲的是「怎么用模板」，属于元信息，生成后无用）

**例外：多仓库工作区不要删。** 多个仓库共享同一套块时，它是注入源，各仓库的 `AGENTS.md` 从它同步；删了就无处可同步。

标记为什么仍要保留（与「用完即删」不矛盾）：项目内的副本删掉后，**项目外的 master 备份仍是外部源**。将来想统一刷新某段的措辞，从 master 改一份再逐项目同步即可。

## 五、索引的增量维护（最容易失效的一环）

`backend.md` / `frontend.md` 里的「可复用能力索引」在**新项目里初始就是空的**——这很正常，不是没做完。

它的正确维护方式是**随开发增量补全**，不是起手时一次性填满：

> **纪律：每新增一个公共能力（基类 / 工具类 / 注解 / hook / 组件 / 接口封装），当次就补进索引表。**

判定标准很简单：**只要你觉得"以后别人（或下次 AI 会话）可能会复用"，就必须补。**
索引不被写下来 = AI 查不到 = 一定会被重写一遍，前面所有规范都会在这一步失效。

## 六、两条硬约束

写进文件的，不是口号：

1. **先分析再实现** —— 拿到需求先输出分析结论，确认后再写代码
2. **先查已有能力，禁止重复实现** —— 新增工具 / 组件 / hook 前先查索引表

## 七、不要做的事

- 不要在 `AGENTS.md` 里写**私有信息**：身份类（姓名 / 邮箱 / 手机号 / 用户名）+ 环境类（本机路径 / 私有端口 / 私有项目名 / 内部机制）。这类**实际值**放 `LOCAL.md`，该文件加进 `.gitignore` 不入库；`AGENTS.md` 只保留引用
- 不要把权威规范的正文复制进 `AGENTS.md`。只做摘要 + 索引，正文留在权威文档，避免双份漂移
- 不要让 `AGENTS.md` 依赖仓库之外的文件。别人单独拉取本仓库时，入口必须仍然可用
- 不要把「还没填的占位符」直接删掉。删了就等于赖账，后面没人记得

| 占位符 | 说明 |

| `{{模块目录}}` | 项目主要模块目录名 |
