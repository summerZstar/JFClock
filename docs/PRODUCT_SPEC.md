# JFClock 产品功能规格 V1.0

> 产品：JFClock（疾风时钟）
> 包名：`com.example.jfclock`
> 技术栈：Kotlin + XML View + Material 3 + Room
> minSdk：23（Android 6.0）
> compileSdk / targetSdk：34
> 当前状态：V1.0 功能开发/验证阶段

## 1. 产品定位

JFClock 是一款以“时间提醒、计时、专注”为核心的 Android 时间工具。

核心原则：

1. **可靠响铃优先于功能数量**。
2. 所有需要后台准点触发的功能尽量复用统一响铃链路。
3. UI 保持简单、现代、易操作。
4. 不为了增加功能而突破“时间工具”的产品边界。
5. 用户运行状态优先本地保存，不依赖云端。
6. Android 系统限制、厂商后台策略必须明确展示给用户。

## 2. 功能结构

### 2.1 闹钟与主界面

主界面：

- 底部 tab 导航：闹钟 / 煮蛋 / 番茄 / 计时器 / 秒表，当前页高亮
- 新增闹钟按钮：圆形，悬浮在底部 tab 上方居中
- 标题行：「闹钟」标题 + 紧跟其后的当前时刻；右上角齿轮进设置页
- 标题下「提醒」行：显示全部闹钟里最近的一次触发时刻（含未到点的稍后提醒），无可响闹钟时整行隐藏

闹钟支持：

- 仅一次（新建默认；所选时分已过时自动顺延到最早可响的一天）
- 每天
- 工作日（跳过周末和法定节假日，调休补班照常）
- 自定义（每周几，可多选；一个都没选不允许保存）
- 每月几号
- 每年几月几日
- 每隔 N 天
- 增强提醒
- 特殊提醒
- 稍后提醒
- 仅跳过下一次
- 开关启停
- 新建/编辑

### 2.2 番茄钟

支持：

- 专注
- 短休息
- 长休息
- 轮数
- 经典 / 深度 / 短冲预设
- 自定义时长
- 暂停 / 继续
- 跳过阶段
- 结束本轮
- 阶段自动衔接
- 后台/锁屏运行
- 番茄响铃页

### 2.3 计时器

支持：

- 时 / 分 / 秒滚轮
- 档位增减（三列迷你档位滚轮 + ± 圆钮；相邻两列的 ± 之间留间距）
- 定时开始（标题 + 摘要 + 开关同排一行；开始时刻已过但「开始 + 时长」未过时按当天算，否则顺延明天）
- 常用计时器预设（可按住手柄上下拖动排序，顺序持久化）
- 自定义名称
- 暂停 / 继续 / 重置
- 后台运行
- 锁屏响铃
- 再来一次
- 停止

### 2.4 秒表

支持：

- MM:SS.CC
- 超过 1 小时显示 H:MM:SS.CC
- 开始 / 暂停 / 继续
- 计次
- 单圈 / 累计
- 最快 / 最慢
- 清零
- 进程回收后恢复
- 手机重启后清零

### 2.5 煮蛋计时

支持：

- 熟度选择
- 大小选择（默认 L 蛋，即 58–68g）
- 冷藏状态
- 自动计算时长
- 自定义时长
- 关键要点
- 详细步骤
- 冰浴计时（默认 4 分钟，蛋好自动开始）
- 后台/锁屏响铃

## 3. 统一响铃架构

闹钟、煮蛋、番茄钟、计时器统一：

```text
AlarmManager
    ↓
XXXReceiver
    ↓
RingService
    ↓
铃声 + 震动
    ↓
对应 RingActivity
```

全屏通知作为兜底。

通知渠道拆分：

- `*_fsi`：高优先级、不发声
- `*_ring`：兜底有声通知

秒表不使用 AlarmManager。

## 4. 数据原则

Room 保存长期业务数据：

- Alarm
- 未来的闹钟历史
- 未来的计时器预设等

SharedPreferences 保存运行态：

- `pomo_timer_prefs`
- `timer_prefs`
- `stopwatch_prefs`

运行态不为了“看起来统一”而强制进入 Room。

## 5. 闹钟计算规则

`repeatType`：

| 值 | 类型 |
|---:|---|
| -1 | 仅一次 |
| 0 | 每天 |
| -2 | 每月几号 |
| -3 | 每年几月几日 |
| -4 | 工作日 |
| -5 | 自定义（每周几） |
| >0 | 每隔 N 天 |

自定义类型的选中星期存在 `repeatDays` 位掩码（位 0 = 周一 … 位 6 = 周日），
排程时从今天起最多看两周，命中选中星期的第一个未来触发点；
列表摘要连续三天及以上压成「周一至五」，全选显示「每天」。

### 月末

例如起始日为 1 月 31 日：

- 2 月没有 31 日 → 2 月最后一天
- 4 月没有 31 日 → 4 月最后一天

### 2 月 29 日

每年重复：

- 闰年 → 2 月 29 日
- 平年 → 2 月 28 日

### 间隔重复

起始日期是数学基准，不是“从今天开始”。

例如：

- 起始日期：9 月 1 日
- 间隔：5 天

则触发日为：

`9/1, 9/6, 9/11, 9/16 ...`

计算时找到当前时间之后的第一个合法触发时间。

## 6. 工作日

数据优先级：

1. 自定义地址
2. GitHub Raw
3. jsDelivr 镜像

缓存：

- 当前年份
- 下一年份
- 30 天过期

数据不可用：

- 回退到周一至周五
- UI 必须明确提示“法定节假日数据未同步”

不能让用户误以为已经使用官方节假日数据。

## 7. Snooze

`Alarm.snoozeUntil`：

- `0` = 无延后
- >0 = 延后触发时间

Snooze 使用：

`requestCode = 9000 + alarmId`

普通闹钟使用：

`requestCode = alarmId`

二者不能互相覆盖。

列表显示：

```text
延后再响 · 还有 4分30秒（07:10）
```

每秒更新文字，不重新绑定整个列表。

## 8. 增强提醒

增强提醒：

- 约 3 秒从 15% 渐强到 100%
- 震动：`0,900,250`
- 每分钟重新拉起响铃界面
- 关闭按钮必须长按 1.2 秒
- Snooze 不受影响

## 9. 特殊提醒

特殊提醒文案：

- 响铃页：26sp、蓝色、粗体、居中
- 通知标题：特殊提醒
- 通知副标题：闹钟标签
- RingService 通知优先显示特殊提醒

## 10. 权限

设置页逐项检查：

- 通知权限
- 精确闹钟
- 全屏提醒
- 后台弹出界面 / 悬浮窗
- 勿扰模式相关能力
- 自启动 / 后台运行（厂商特有）
- 节假日数据

权限不足时提供明确说明和跳转入口。跳转落点按开关实际位置区分：

- 后台弹出界面 / 锁屏显示 → 直达 ColorOS 特殊应用权限页，失败退**本应用应用详情页**（开关在「应用信息 → 其他权限 → 特殊权限」）；
- 自启动 → 直达厂商自启动管理，失败打开 **`设置 → 应用`**（不是应用列表页），再退才落到设置首页。

## 11. 开机恢复

V1.1 必须考虑：

- 普通重复闹钟开机重排
- 一次性未来闹钟开机重排
- 未结束计时器根据墙钟结束时间恢复
- 番茄钟根据保存的结束时刻恢复

秒表继续保持“手机重启后清零”的产品定义。

## 12. 非目标

暂不加入：

- 日历
- 天气
- 喝水提醒
- 任务管理
- 记账
- AI 助手
- 社交
- 云同步

除非后续产品定位发生变化。

## 13. 成功标准

JFClock 的核心成功标准不是功能数量，而是：

> 用户设置一个闹钟后，即使切换 App、锁屏、后台运行，也能在系统允许的条件下可靠地提醒用户，并明确告知可能影响可靠性的权限和厂商设置。
