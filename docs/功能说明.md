# JFClock 功能说明

> 面向使用者与后续维护者的功能文档。覆盖「重复方式扩展 / 增强提醒 / 工作日闹钟 / 番茄时钟」「计时器 / 秒表 / 延后再响可见」「计时器按 ColorOS 重做 / 自绘丝滑滚轮替换 NumberPicker / 煮蛋页新增冰浴计时」「闹钟默认仅一次 / 重复方式加自定义周几（折叠成一行 + 弹窗）/ 列表「下次响铃」并进第二行双色显示」，以及本轮的「主界面入口改底部 tab（加号改圆形悬浮）/ 标题行时间与「提醒」行 / 计时器定时开始同天规则 + 档位 ± 分开 + 定时开始一行化 / 常用计时器拖动排序（DB v8）/ 煮蛋默认 L 蛋 / 权限页跳转落点修正」。
> **本轮改动已在本机 `assembleDebug` + 单测跑通（见文末「待验证」），但按要求尚未推送**，GitHub Actions 上还没有对应的 run。

- 最低系统版本 Android 6.0（minSdk 23），target/compile SDK 34
- 界面为 Kotlin + XML View + Material 3（非 Compose），数据用 Room
- 包名 `com.example.jfclock`

## 1. 功能总览

| 模块 | 入口 | 说明 |
|---|---|---|
| 闹钟 | 主界面（底部 tab「闹钟」） | 列表 + 开关 + 新建/编辑，标题行右侧显示当前时刻，标题下方一行「提醒 · …」显示全部闹钟里最近的一次触发时刻 |
| 煮蛋计时 | 底部 tab「煮蛋」 | 熟度 × 大小 × 冷藏算时长，到点后台响铃；页内另有**冰浴计时**（默认 4 分钟，蛋好自动开始） |
| 番茄时钟 | 底部 tab「番茄」 | 专注 → 短休息，攒满轮数换长休息，阶段自动衔接 |
| 计时器 | 底部 tab「计时器」 | ColorOS 风格大圆环 + 时/分/秒滚轮 + 三列档位滚轮加减 + 定时开始 + 常用计时器预设（秒表/铃铛图标区分类型，支持拖动排序），到点全屏响铃 |
| 秒表 | 底部 tab「秒表」 | 大字号 分:秒.百分秒 + 计次（单圈/累计）+ 清零 |
| 权限与数据 | 主界面右上角齿轮 | 后台响铃所需权限逐项检查 + 节假日数据同步 |

四个工具入口固定在**底部 tab 栏**（闹钟 / 煮蛋 / 番茄 / 计时器 / 秒表），当前页高亮；新增闹钟按钮改成**圆形悬浮按钮**，压在 tab 栏上方居中；右上角齿轮保持不变。
凡是选数字的地方（闹钟时分、稍后提醒分钟、计时器三列、煮蛋与番茄钟的时长对话框）都换成自绘的 `WheelPicker`，手感见 4.1。

所有需要「到点提醒」的地方都走 `AlarmManager`，响铃由同一个前台服务 `RingService` 承担：
闹钟、煮蛋、冰浴、番茄钟、计时器共用一套后台响铃链路，只是拉起的界面不同。秒表不需要准点唤醒，只做状态持久化。

## 2. 闹钟

### 2.1 标题行时间 + 「提醒」行

主界面标题行 = 「闹钟」大字 + 紧跟其后的当前时刻（`tvClock`，随秒刷新）+ 右侧齿轮；标题下方一行 `tvReminder`：

- 显示 `提醒 · 今天 07:30` 这样的**下一次响铃**，取全部闹钟里最近的一次触发时刻（含未到点的「稍后提醒」），时刻已过就用当天/明天/`M月d日` 描述（`describeDayTime`）。
- 没有可触发的闹钟时整行隐藏（不再显示「还没有启用的闹钟」这类占位）。
- 只在缓存时刻过去、或闹钟列表变化时才重新遍历计算（`nextTriggerOf`），平时只按秒刷新文案；文案与上一帧相同就不写 View。
- 启动 App 时**额外弹一次 Toast**（含具体日期时间），只在本次启动提示一次；新建/保存闹钟、手动打开某个闹钟时也会各提示一次。

### 2.2 重复方式

编辑页「重复」折叠成一行（左侧「重复」+ 右侧蓝色摘要 + `›`），点击弹窗单选：
**仅一次 / 每天 / 工作日（法定节假日休）/ 自定义（每周几）/ 每月几号 / 每年几月几日 / 间隔重复（每 N 天）**。
选中即生效、弹窗关闭，子参数按类型在下面就地展开：起始日期行（仅一次 / 每月 / 每年 / 间隔）、星期圆钮（自定义）、间隔天数 ± 行。

数据库里 `repeatType` 的含义：

| 值 | 含义 | 与「起始日期」的关系 |
|---|---|---|
| -1 | 仅一次 | 就在起始日期那天响一次，过了不再响（**新建默认**；时分已过时保存前自动顺延到最早可响的一天） |
| 0 | 每天 | 无关 |
| -2 | 每月几号 | 取起始日期的「几号」；小月没这天则落到当月最后一天 |
| -3 | 每年几月几日 | 取起始日期的「月 + 日」；2/29 在平年落到 2/28 |
| -4 | 法定工作日 | 无关（跳过周末与节假日，调休补班日照常响） |
| -5 | 自定义（每周几） | 无关；选中星期存 `repeatDays` 位掩码 |
| >0 | 每隔 N 天 | 起始日期当天算第 0 天，N = repeatType |

**自定义（每周几）**：7 个圆形按钮（一~日）可多选，位 0 = 周一 … 位 6 = 周日（`Alarm.weekdayBit`），存进新增列 `repeatDays`。
列表文案连续三天及以上压缩成「周一至五」，否则逐个列出（如「周一、三、五」「周六、日」），全选显示「每天」；
一个都没选时保存会被拦下并提示「请至少选择一天」。排程从今天起最多看两周（15 天），命中选中星期的第一个未来触发点，
「跳过一次」跳掉唯一那一天时也能正确落到下周同一天。

**新建默认「仅一次」**：时间默认拨到**下一个整点**（避免默认 00:00 一保存就已过）；若所选时分已过，
保存时按最早可响的一天写回起始日期（UI 层 `effectiveOnceTime()`），起始日期下方提示里写明实际响铃日期
（如「只响一次：明天 09:00」），不会出现「开关亮着但永远不响」的假闹钟。

**起始日期选择器**：仅一次 / 每月 / 每年 / 间隔重复 四种方式下显示（点「起始日期」调系统日期选择器），下面有一行灰色说明当前号数/日期的效果。每天、工作日与自定义不受起始日期影响，因此隐藏。

> 注意：起始日期是「数学位」而非「生效开关」。若把间隔 5 天的起始日期设成过去，程序会从那天起按 5 天步进推进，直到找到晚于当前时间的第一个触发点，而不是「从今天才开始数」。

### 2.3 增强提醒

打开编辑页「增强提醒」开关后，到点时：

- 铃声从 15% 音量在约 3 秒内渐强到满音量（`MediaPlayer` 实现，普通模式仍用系统 `Ringtone` 循环）；
- 震动改为长脉冲 `0,900,250`（普通为 `0,600,400`）；
- 响铃界面被划掉后，前台服务每分钟重新拉起一次；
- 关闭按钮变成「长按关闭」，需按住 1.2 秒才生效，避免半睡状态误触抹掉提醒。「稍后提醒」不受影响。

### 2.4 特殊提醒

编辑页「特殊提醒」输入一句话（如「吃降压药」「接孩子」）：

- 响铃界面在标签下方用 26sp 蓝色粗体居中显示；
- 通知栏以这句话作标题，标签作副标题，一眼看到要做什么；
- 前台服务的通知同样优先显示这句话。

主界面列表里，开启了增强提醒的闹钟会在第二行末尾追加「增强」标记。

### 2.5 工作日闹钟与节假日数据

**为什么不是直接解析国家网站**：国务院办公厅只发布 HTML 公告（没有结构化接口，页面一改版就失效）。因此采用由该公告自动同步生成的 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 数据集，每年一个 JSON，字段里带着官方公告链接，可以溯源。

实现要点（`WorkdayCalendar`）：

- 依次尝试：自定义地址（若有）→ `raw.githubusercontent.com` → `cdn.jsdelivr.net` 镜像；
- 解析 `days[].date / isHoliday`，得到「某日是否放假」；调休补班日 `isHoliday=false`，即周六也上班；
- 缓存今年 + 明年，30 天视为过期后自动重新拉取；App 启动时只读本地缓存，不联网；
- **全部失败时退回「周一至周五」**，并且界面会明确标注还没拿到数据，避免误以为已按法定节假日生效；
- 网络请求在 IO 线程执行，超时 8 秒。需要在权限页手动点「立即同步」时也会重排所有工作日闹钟。

新增权限：`INTERNET`、`ACCESS_NETWORK_STATE`。

### 2.6 关闭重复闹钟时的「仅跳过一次」

主界面关掉一个重复类闹钟（非「仅一次」）会弹两选项：

- 仅 X 月 X 日关闭一次：闹钟保持开启，只把下一次触发时间写进 `skipTime`；
- 关闭此重复闹钟：直接停用并清掉 `skipTime`。

### 2.7 稍后提醒（延后再响）在列表里可见

点「稍后提醒」后，闹钟列表项里会多出一行蓝色小字（第三行，排在「重复方式 + 下次响铃」行之下），例如：

```
延后再响 · 还有 4分30秒（07:10）
```

- 数据来源是 `Alarm.snoozeUntil`（延后再响的那一时刻，0 表示没有）；响过一次、停用、编辑保存都会清零。
- 这一行每秒更新剩余时长（主界面按整秒 tick，`refreshStatusLines`），只改文字、不重绑列表（否则开关会闪）。
- 延后再响到点后不再显示，闹钟恢复正常的「每天/工作日…」第二行文案。
- 标题下的「提醒」行会把延后再响的时刻一起算进去——延后的那一次通常更早，所以显示的是它。
- 排程上「延后再响」用独立的 `PendingIntent`（`requestCode = 9000 + id`），与正常排程（`requestCode = id`）互不顶掉：延后响完只清掉延后，明天照常响的时间还在。停用闹钟（`AlarmScheduler.cancel`）会连同延后一起取消。

### 2.8 列表第二行：重复方式 + 下次响铃合并（双色）

原来「下次响铃」独立占一行蓝色文字，卡片被撑得很高。现在并进第二行，一块次要色一块主题蓝：

```
每天 · 还有8小时23分后响
周一、三、五 · 明天响
仅一次 · 9月30日响
```

- 实现是把 `descText` 渲染成 `SpannableStringBuilder`：前半 `describeAlarm(alarm)`（重复方式 + 标签 + 增强标记，次要色），
  后半 `formatNextRingLine(...)`（主题蓝 `light_accent`），中间用 ` · ` 连接；关闭的闹钟不追加上次响铃段。
- 「下次」文案特意只给**天级**信息（`即将响铃` / `还有X小时Y分钟后响` / `明天响` / `M月d日响`），
  具体时分看卡片左侧的大字，保证 360dp 窄屏也能单行放下。
- 仍是「只在渲染粒度变化时才写 View」：`tag = 重复方式哈希 × 31 + nextRingStamp(next, now)`，
  逐秒刷新时绝大多数行零写入。
- 「稍后提醒」与「已跳过」文案长且每秒倒数，继续单独放第三行（`snoozeText`），此时第二行只留重复方式。

## 3. 番茄时钟

主界面「番茄钟」进入。一个番茄 = 一段专注 + 一次短休息；攒满设定的轮数后换成一次长休息。

- 界面：大倒计时 + 当前阶段（专注/短休息/长休息 + 分钟数）+ 轮次信息（第 N/M 个番茄 · 已完成 X 个）+ 进度条 + 状态说明。
- 节奏预设三个一键切换：经典 25/5/15（每 4 轮）、深度 50/10/30（每 2 轮）、短冲 15/3/10（每 4 轮）；点齿轮或「时长设置」行可逐项用滚轮改（专注 ≤180、短休 ≤60、长休 ≤120、轮数 2–12）。
- 按钮：开始专注 / 暂停 / 继续 / 开始下一阶段（随状态变化）、跳过本阶段、结束本轮。
  - **暂停**会取消排程并记下剩余时间，继续时按剩余时间重新排程；
  - **跳过本阶段**直接进入下一阶段，且不计入已完成的番茄数；
  - **结束本轮**取消排程并清零轮次。
- 「阶段自动衔接」开关（默认开）：开 → 一个阶段响完立刻把下一阶段排到 `AlarmManager`，人不在 App 里也能连续转；关 → 停在「等你点开始」状态。
- 到点提醒与闹钟同一链路：前台服务响铃 + 全屏意图通知 + 锁屏响铃页（`PomoRingActivity`）。响铃页有两个按钮：
  - 「打开番茄钟」只停铃声，自动衔接好的下一阶段继续跑；
  - 「结束本轮」才真正取消排程。
- 状态存在 `pomo_timer_prefs`（SharedPreferences，墙钟结束时刻），切到别的 App、锁屏、杀进程重进都能恢复；通知渠道为「番茄时钟」（静默，声音归服务）与「番茄响铃（兜底）」（服务被拒时由通知发声）。

## 4. 计时器（倒计时）

参考 ColorOS 时钟的倒计时页，主界面「计时器」进入。

- **大圆环 + 中心读数**：一页只有一个 232dp 的圆环（`CircularProgressIndicator`，轨道浅灰、进度蓝色），环内居中是 `MM:SS` / `H:MM:SS` 大字和一行副标题（「预计 14:32 结束 · 泡茶」）。圆环按**剩余比例**走，开始是满环、到点空环，比「已走比例」更贴近 ColorOS 的直觉。
- **设时长**：时 / 分 / 秒三列滚轮（0–23、0–59、0–59），滚轮是本项目自绘的 `WheelPicker`（见 4.1）。
- **档位增减（我们的特色）**：ColorOS 只给「+1 分钟」，这里在时长滚轮下面排**三列迷你档位滚轮**，每列左边一个「−」圆钮、右边一个「+」圆钮：
  - 小时档 `01 02 03 06 12`、分钟档 `01 05 10 15 30 45`、秒钟档 `05 10 15 30 45`（循环滚动，档位由 `TimerActivity` 的 `HOUR_STEPS / MINUTE_STEPS / SECOND_STEPS` 定义）；
  - 滚到想加的档位，点一侧就加、点另一侧就减，**可连点累加**，一行放得下、不再需要横向滑动；三列是**三块独立小组**，块与块之间留 16dp（`TimerActivity.buildDeltaColumn` 在两列之间插一个 `Space`），否则左列的「+」和右列的「−」会挨在一起、看起来像同一组按钮。
  - 间距**只能加在列与列之间**：加在列内部（给 ± 圆钮加外边距）会挤扁中间的滚轮，把「小时档 / 分钟档 / 秒钟档」这行单位文字逼到换行，三列还会因为行高不一致显得错位。`tvDeltaUnit` 另加 `maxLines="1"` 兜底，单位文字永不再换行。
  - 点一下上方的三列时长滚轮会**动画滚到位**（不是硬跳到新数字），总量按 0–23:59:59 夹紧；减到底就停在 0，此时点开始会提示「请先把时间拨到 1 秒以上」。
  - 列布局 inflate `view_timer_delta_col.xml`，圆钮样式 `@style/TimerStepButton`。
- **定时开始**：「定时开始」标题、一行蓝色摘要、开关**同排一行**（开关关着显示「点开始立即倒数」，开着且时长有效时显示「今天 14:32 开始 · 14:47 响铃」）；点这一行弹出**时 / 分两列滚轮**（`view_timer_start_time.xml`，与时长同款 `WheelPicker`，不再用系统 MaterialTimePicker 的表盘/输入框）选一个时刻。
  - **同天规则**：确认后按墙钟算下一次该时刻（`TimerStore.nextOccurrence`）。开始时刻已过去时再看「开始 + 时长」是否也过去了——结束还在未来就**按当天算**（这轮今天照样能触发，不定到明天）；结束也过了、或时长还没拨（为 0），才顺延到明天同一时刻。摘要文案与 `onStartClicked` 走的是同一个算法。
  - 到点才开始倒数，等待期间圆环显示「已定时，等待开始」，此时点「开始」= 取消定时。
- **常用计时器（预设）**：点条目把时长、名称**和类型**一起回填拨盘（不自动开始），长按条目可编辑/删除。条目左侧的图标就是类型标识 —— **秒表图标**=手动倒计时，**铃铛图标**=定时开始，且铃铛条目下方多一行副标题直接写出几点开始（如「07:30 开始」）。预设存 Room `timer_presets`（v6 起含 `startHour` / `startMinute`，`startHour = -1` 即普通倒计时）。新建/编辑对话框里用开关切换类型，打开后才露出时/分两列开始时刻滚轮。
  - **拖动排序**（v8 起）：列表改成 `RecyclerView`（`TimerPresetAdapter`），条目右侧多一个手柄图标，**按住手柄上下拖**即可换位（长按条目本身仍是编辑，二者不冲突）；松手后把新顺序写回 `sortOrder`（`TimerPresetDao.updateOrder`），列表按 `sortOrder ASC, id ASC` 查询，**重启后顺序保持**。顺序与库里一致时不写库，避免每次拖动整表更新。列表上方有一行灰字说明「点一下套用 · 长按编辑 · 按住右侧手柄可上下排序」。
- **名称（可选）**：填了会显示在环内副标题、响铃界面与通知上，例如「泡茶」。
- **走时**：开始后滚轮、档位增减排、名称输入框一起隐藏，只留圆环和读数。停表回到拨盘时会把滚轮**回填成上一轮的时长**（名称也回填），方便原地重开。
- **按钮**：开始 / 暂停 / 继续（随状态切换）+ 重置。暂停时取消排程并记下剩余毫秒，继续时按剩余时间重新算结束时刻；重置在停表状态也常驻（比开始按钮小一圈），点一下把拨盘清零成 `00:00:00`，计时中/暂停点它则停表回到拨盘、已拨时长与名称保留。
- **后台准点**：与闹钟同一条链路 —— `TimerScheduler`（`AlarmManager.setAlarmClock`，无精确闹钟权限时三级降级）→ `TimerReceiver` → `RingService`（`KIND_TIMER = 3`）→ 全屏响铃页 `TimerRingActivity`（锁屏可见、点亮屏幕）。通知渠道为「计时器」（静默）与「计时响铃（兜底）」。
- **响铃页两个按钮**：
  - 「再来一次」：按刚才的时长立刻重新倒数并重新排程，页面可以直接关掉，到点照样响；
  - 「停止」：结束本次计时，状态清零。
  - 服务没起来时页面自己播铃声 + 震动兜底（与其它响铃页一致）。
- 状态存在 `timer_prefs`（SharedPreferences，保存墙钟结束时刻、总时长、剩余时长、名称），因此切到别的 App、锁屏、进程被回收后回来读数依然准确。
- 已知边界：重启手机后 `AlarmManager` 的排程会丢失（与其它计时类功能一致，未在开机后重排正在跑的计时器）。

### 4.1 滚轮为什么自己画（`WheelPicker`）

系统 `NumberPicker` 的手感与 ColorOS 差得比较明显：拖动几乎不带惯性、松手吸附很硬、上下项与中间项的明暗差别固定，看着像表格而不是轮盘；另外它的字色只能靠反射改私有 `Paint` 字段（就是之前那个 `styleNumberPicker`，在部分 ROM 上直接失效）。因此自绘一个 `View`，不引第三方依赖（项目的 CI 只配了 Google Maven，加 jitpack 会带来额外失败点）。

对外 API 刻意与 `NumberPicker` 对齐（`minValue` / `maxValue` / `value` / `wrapSelectorWheel` / `setFormatter` / `setOnValueChangedListener`），所以替换时业务代码几乎没改动；XML 属性统一带 `wheel` 前缀（`wheelMinValue`、`wheelItemTextSize`、`wheelVisibleCount`…），避免与库里同名 attr 冲突。

实现要点：

- 内部位置是**浮点数**（单位「格」），手指位移直接映射成位置，所以拖动跟手；
- 松手用 `VelocityTracker` 估速，按 `speed × 0.6s` 算惯性距离，再用 ease-out 三次曲线吸附到整格（时长随距离在 130–640ms 之间取）；
- 每跨过一格给一次 `CLOCK_TICK` 轻触觉，并在值变化时回调；
- 中间画两条分隔线，上下项按距中心的比例做透明度与字号衰减（越远越淡越小），做出景深；
- 轻点某一格会把那格滚到中心（系统控件只能靠拖）；
- 循环模式（如分钟 0–59）取**离当前位置最近的一圈**，不会为了从 59 到 0 转大半圈。

已替换的位置：闹钟编辑页的时/分与「稍后提醒」分钟、计时器三列、煮蛋的自定义时长与熟度基础时长对话框、番茄钟的四项时长设置对话框。`AlarmUtils.styleNumberPicker`（反射改 `NumberPicker` 字色的那段）连同调用一起删除。

## 5. 秒表

主界面「秒表」进入，只做本地计时，不需要系统闹钟。

- **读数**：大字号 `MM:SS.CC`（分:秒.百分秒），超过 1 小时自动变 `H:MM:SS.CC`；界面每 50ms 刷一次，用了 `tnum` 等宽数字避免跳动。
- **按钮**：开始 / 暂停 / 继续（同一按钮随状态切换）、计次、清零。只有走时中「计次」才可点（不可用时灰掉）。
- **计次表**：表头「次数 / 单圈 / 累计」，最新一次在最上面；正在计时的最后一行用蓝色高亮。计次 ≥3 次时，最快/最慢的单圈会在次数后面标注「最快」「最慢」。
- **基准是 `SystemClock.elapsedRealtime()`**（开机以来的毫秒数），不是墙钟：所以熄屏、切 App、改系统时间都不会让读数跳变；累计时长与起点、计次列表都写进 `stopwatch_prefs`，页面销毁或进程被回收后回来仍然连续。
- 唯一例外是**重启手机**：`elapsedRealtime` 归零，此时按「已清零」处理（`elapsed()` 里用 `now < startAt` 判定），不会出现负数或天文数字。

## 6. 煮蛋计时

- **默认大小 L 蛋**：进页面默认选中 L（熟度仍默认第一个）。国内鸡蛋分级是 M 48–58g / L 58–68g / XL 68g以上，日常买到的散装或盒装蛋多落在 58–68g 这一档，所以默认 L 更贴近大多数人手里的蛋，少按一次。大小 chip 下方也标了这三档的克数。
- **选中态不再丢失**：进入「自定义时长」后，之前选的熟度与大小 chip 仍保持高亮。自定义只覆盖最终时长，不改变已选项；点任一熟度/大小会自动退出自定义。
- **关键要点前置且默认展开**：开始/停止按钮下方紧跟一张「关键要点」卡，两条重点常驻显示——
  - 沸水下锅：水完全烧开后再放蛋，下锅转中火保持微沸，从这时开始计时；
  - 冰浴 3–5 分钟：到点立刻捞进冷水或冰水，止住余温继续加热，也更易剥壳。
- 「怎么煮更稳」的详细步骤卡改为**默认展开**（仍可手动收起）。
- 首屏仍能看到「开始」按钮（要点卡放在按钮之后，不把它挤出屏幕）。
- 到点走 `EggScheduler` + `RingService`，后台/锁屏同样能响。

### 6.1 冰浴计时（默认 4 分钟）

煮蛋页的开始/停止按钮下面新增一张紧凑的「冰浴计时」卡，把要点里那句「冰浴 3–5 分钟」变成能一键执行的动作。

- **时长**：默认 4 分钟，`−` / `+` 以 30 秒步进，范围 1–15 分钟；中间的数字就是设定值（`MM:SS`），跑起来后变成实时倒计时。
- **蛋好自动开始冰浴**（开关，默认开）：`EggReceiver` 在煮蛋到点时顺手把冰浴排上（`IceStore.startNow`），捞蛋下水不用再去点一次；已经有一个冰浴在跑时不会被覆盖。
- **手动**：随时点「开始冰浴」（比如蛋已经在锅里就想先冰个饮料），跑起来后按钮换成「取消冰浴」。
- **与煮蛋互不打架**：冰浴单独一套 `IceStore`（`ice_prefs`）/ `IceScheduler`（requestCode 5021、51021，与煮蛋的 5001、51001 错开）/ `IceReceiver`（通知 id 52002，渠道「冰浴计时」+「冰浴响铃（兜底）」），所以煮蛋还在倒数时也能开冰浴，两个计时各自准点响。
- **响铃**：`RingService.KIND_ICE = 4` → `IceRingActivity`，复用煮蛋响铃的布局与蓝白深色配色，标题换成「冰浴时间到」，按钮是「再来 1 分钟」和「关闭」；服务没起来时页面自己播铃声 + 震动。
- 服务复用时先 `stopFeedback()` 再起新一轮铃声，避免煮蛋与冰浴相隔几分钟先后到点时两份铃声叠加。

## 7. 后台响铃链路（闹钟 / 煮蛋 / 冰浴 / 番茄钟 / 计时器共用）

Android 10+ 禁止后台进程直接 `startActivity`，广播里那句 `startActivity` 在切到别的 App 时会被系统静默丢弃（只有通知能出）。因此：

1. `AlarmManager.setAlarmClock` 到点 → `AlarmReceiver` / `EggReceiver` / `IceReceiver` / `PomoReceiver` / `TimerReceiver`；
2. 广播里请求前台服务 `RingService`（`startForegroundService`），服务类型 Android 14 起申报为 `specialUse`（子类型 `alarm_ringing`）；
3. 服务负责：播铃声（增强提醒走渐强）+ 震动 + 拉起对应响铃界面；
4. 同时仍发一条全屏意图通知（`setFullScreenIntent`）作为兜底，通知点进去也能响铃；
5. 服务被系统拒绝（Android 12+ 后台启动前台服务受限）时，退回「有声通知」渠道，铃声由通知发，界面靠用户点击或悬浮窗权限弹出。

通知渠道按用途拆分（渠道声音创建后不可更改，所以只能拆）：

- `*_fsi`：高优先级但不发声，声音由服务播，避免双份铃声；
- `*_ring`：兜底，直接带闹钟声与震动。

响铃界面统一带 `showOnLockScreen` / `turnScreenOn` / `excludeFromRecents` / `singleTask`，并在代码里 `setShowWhenLocked` + `setTurnScreenOn`（API 27+）。

## 8. 权限与设置页

齿轮进入「闹钟权限」，逐项显示状态（已开启 / 去开启 / 手动设置），点击直达对应系统设置页，找不到页面时提示手动前往。

| 项目 | 作用 |
|---|---|
| 通知权限 | Android 13+ 需运行时授权，否则全屏通知被静默丢弃 |
| 闹钟和提醒（精确闹钟） | 未授予时降级为非精确排程，省电模式可能延迟几分钟 |
| 全屏提醒 | Android 14+ 需单独允许，否则到点只有通知、不弹响铃界面 |
| 悬浮窗（显示在其他应用上层） | 系统悬浮窗权限，部分机型锁屏/后台弹响铃界面靠它；点击直达悬浮窗设置 |
| 勿扰模式下响铃 | 可选，勿扰时仍能响 |
| 自启动 / 后台运行 | 仅 OPPO 系显示，必开，否则清理后台后广播收不到 |
| 节假日数据（工作日闹钟） | 常驻行：显示上次同步时间与公告来源；点按立即同步，长按自定义数据地址 |

其中三项没有公开 API 可读状态、显示「手动设置」——**后台弹出界面、锁屏显示、自启动（仅 OPPO 系）**，点击后的落点按开关实际所在位置区分：

- **后台弹出界面 / 锁屏显示**：这两个开关在 `应用信息 → 其他权限 → 特殊权限` 里。先试直达 ColorOS 特殊应用权限页，打不开就退到**本应用的应用详情页**（`PermUtils.appDetailsIntent`），用户从「其他权限 → 特殊权限」两级点进去即可。
- **自启动**：开关挂在 `设置 → 应用` 这一级下面。先试 ColorOS 自启动管理页，打不开就打开 **`设置 → 应用`**（`PermUtils.settingsApplicationsIntents`：优先厂商 `Settings$ApplicationsSettingsActivity`，不行再落到设置首页 `ACTION_SETTINGS`）。**刻意不用 `ACTION_MANAGE_APPLICATIONS_SETTINGS`**——那是应用列表，比「应用」页低一层，从那里根本走不到自启动。

ColorOS 私有的「后台弹出界面」与标准悬浮窗是两项：前者在特殊应用权限里手动开，后者本页可直达。

主界面在关键权限缺失时显示一行提示（可点进设置页）；首次启动弹一次引导对话框。
保存闹钟/开启闹钟时若缺精确闹钟权限，会弹「去开启 / 先保存」的引导。

## 9. 数据与兼容性

- Room 数据库版本 2 → 3 → 4 → 5 → 6 → 7 → 8（库版本 2.6.1），手写迁移、`exportSchema = false`，老数据无需清库即可升级：
  - `MIGRATION_2_3`：新增 `intenseAlert INTEGER NOT NULL DEFAULT 0`、`specialNote TEXT NOT NULL DEFAULT ''`；
  - `MIGRATION_3_4`：新增 `snoozeUntil INTEGER NOT NULL DEFAULT 0`（延后再响的时刻）；
  - `MIGRATION_4_5`：新建 `timer_presets` 表（计时器预设）；
  - `MIGRATION_5_6`：`timer_presets` 新增 `startHour INTEGER NOT NULL DEFAULT -1`、`startMinute INTEGER NOT NULL DEFAULT 0`（-1 表示普通倒计时，非负为「定时开始」时刻）；
  - `MIGRATION_6_7`：`alarms` 新增 `repeatDays INTEGER NOT NULL DEFAULT 0`（自定义周几位掩码，位 0 = 周一 … 位 6 = 周日；0 = 未选/不适用）；
  - `MIGRATION_7_8`：`timer_presets` 新增 `sortOrder INTEGER NOT NULL DEFAULT 0`（拖动排序位置，查询按 `sortOrder ASC, id ASC`）。
- `Alarm` 新增字段：`snoozeMinutes`、`skipTime`（v1→v2）、`intenseAlert`、`specialNote`（v2→v3）、`snoozeUntil`（v3→v4）、`repeatDays`（v6→v7）；`TimerPreset` 新增 `sortOrder`（v7→v8）。
- 新增的 SharedPreferences 文件：`timer_prefs`（计时器）、`stopwatch_prefs`（秒表）、`ice_prefs`（冰浴：时长设置、自动衔接开关、运行时刻），沿用番茄钟的 `pomo_timer_prefs` 与煮蛋的 `egg_timer_prefs`；都不进 Room，避免为临时运行态加表。
- 各链路的 `AlarmManager` PendingIntent requestCode 互相错开，避免相互取消：闹钟 id / `9000+id`（延后再响）、煮蛋 5001/51001、冰浴 5021/51021、番茄 5301/54001、计时器 5601/56101。
- `Ringtone.setAudioAttributes` / `isLooping` 是 API 28+，已收进 `SDK_INT >= P` 分支；更低版本用定时重播近似循环。
- Android 14 的合法 `foregroundServiceType` 里没有 `alarm`，因此用 `specialUse` + `FOREGROUND_SERVICE_SPECIAL_USE` 权限 + `<property>` 子类型声明。
- 全屏提醒授权页用字面量 `"android.settings.MANAGE_APP_USE_FULL_SCREEN_INTENT"`，规避 SDK 常量缺失。
- 未授予精确闹钟权限（部分 ColorOS）时排程三级降级：`setAlarmClock` → `setExactAndAllowWhileIdle` → `setAndAllowWhileIdle`，保证不崩、能响。
- 任何异常通过 `reportCrash` 把堆栈复制进剪贴板并弹 Toast，方便用户粘贴反馈。
